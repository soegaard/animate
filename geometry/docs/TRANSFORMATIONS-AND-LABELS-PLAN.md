# Plan and implementation: transformations and semantic labels (v0.9.0)

## Scope and baseline

Extend the delivered v0.8.3 geometry directory, retaining the audited/scalene
examples, short equality ticks, right-angle size, one-second reading delay,
review bundles, process workers, and static-frame reuse. The parent Animate
checkout is not modified. The repository head observed for native API reference
was `bf61135fabe059c5b8b98d6786a417c55062ac3e`; the delivered directory contains
later geometry-only refinements and is therefore the implementation baseline.

## 1. Mathematical contract

Use invertible Euclidean similarities rather than unrestricted affine matrices.
Translation, rotation, reflection in a Line, and nonzero dilation preserve the
supported geometric kinds. In particular, a circle stays a Circle, not an
unrepresented ellipse. Negative dilation is allowed; zero dilation is rejected
rather than silently collapsing a Line, Ray, Circle, or Angle.

Add nondrawable Vector and Transform values, named bindings, composition,
inversion, typed helper inputs/results, and convenient direct operations.
Rotation input is radians; `(degrees n)` is the explicit conversion. Composition
uses mathematical order: `(compose-transform T S)` applies S before T.

Implement one immutable similarity representation and map the defining points of
Point, Segment, Line, Ray, Circle, and Angle. Map supported Relation and Marker
values through the same operation. Relations remain assertions to check, not
proofs generated by the renderer. Shape transforms do not copy source styling,
name labels, camera settings, or annotation positions.

## 2. Semantic label contract

Add a drawable Label value with an immutable target and text:

- `point-label`: an independently controlled name at a point.
- `segment-label`: authored text attached to a segment.
- `length-label`: symbolic text or a computed segment length.
- `angle-label`: symbolic text or a computed minor-angle measure in degrees,
  with an optional arc (enabled by default).

Labels are not Euclidean loci or geometric assertions. A literal "5 cm" is not
validated as a measurement. A computed label takes its value from its target;
`#:unit` adds a suffix, not a unit conversion. Formatting is resolved once at
realization, never repeatedly at every video frame.

Point labels do not silently rename their targets or suppress automatic point
names. Authors use `hide-label` to avoid duplicate names, or keep the existing
`layout/label-text` facility when only a rename is needed. Independent labels can
remain visible when their target is hidden, just like independent markers.

## 3. Compiler and evaluation integration

Extend the closed expression vocabulary and typed values, including Text helper
arguments. Reject type/arity/option mistakes before rendering. Keep all existing
helper hygiene, result aliases, auxiliary cleanup, dependency inspection, and
numeric realization contracts. Add label-position to the annotation hints that
follow result aliases during helper expansion.

Transformations and labels are realized once; no per-frame updater is added.
The first-class transformation is not a motion animation. A newly bound image
uses the existing type-specific reveal policy. Label text uses the existing
native text API and stays upright, including beside reflected geometry.

## 4. Placement and styling

Use the existing visibility-aware annotation planner and native font metrics.
Segment/length labels choose a point along their target and an offset normal to
it. Angle labels stay in their angular sector; optional arcs use the existing
marker geometry without asserting equality. Point labels use point-relative
candidates. Reserve measured ink boxes alongside markers, points, curves, and
caption space. Placement remains fixed throughout playback.

Support existing `label-side`, `label-at`, adapter overrides, and `label-text`.
Extend `label-offset` to Label (relative to point, segment midpoint, or angle
vertex), and add `(label-position id fraction)` for dimension labels.
`marker-radius` also accepts an angle Label. Add semantic-label and subtype theme
selectors; retain world-unit font/offset sizes and cosmetic stroke widths.

## 5. Examples and documentation

Add two independently runnable videos: transformations and semantic-labels.
Extend the gallery with reflection, translation, half-turn, dilation, symbolic
labels, and computed measurements. Register both new videos with review --all
and --example, but do not add them to the thirteen straightedge/compass library
applications. Keep captions about the mathematics rather than announcing
emphasis operations.

Update the reference manual, gallery guide, review guide, source notes, and
release notes. All code remains inside geometry/.

## 6. Verification

Run independent coordinate oracles for reflection/rotation and composition;
check inverse round trips, handedness, incidence, rays, circles, angle measure,
negative scales, singular inputs, relation/marker mapping, and immutability.
Check DSL typing, Text/Transform/Label helper composition, label formatting,
visibility, pins and offsets, annotation sectors, theme inheritance, and review
snapshots. Re-run the existing library, audit, refinement, and review checks.

Include native integration checks for measured labels, sampling, text/arc
Visuals, and PNG output in both themes. Report native execution separately from
headless execution; reader success is not a substitute for compiling/rendering
against the complete Animate dependency set.

## Explicit boundaries

No shears/nonuniform scaling, animated givens, morph-to-transform animation,
physical ruler/compass tools, formal proof engine, TeX labels, dynamic unit
conversion, or automatic inheritance of source annotations is introduced.
A transformed label is made by labelling the transformed target, not by flipping
or scaling its glyphs. Small/straight/degenerate angle labels outside the
supported nondegenerate minor-angle range are diagnosed explicitly.
